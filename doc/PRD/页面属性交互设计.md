# PRD-05：页面属性体系交互重设计（Page Properties UX v2）

> 状态：待评审（设计定稿，未开发）
> 版本：v0.1
> 日期：2026-07-25
> 定位：`mydocmost` 内网 / 离线定制 Fork（Docmost v0.24.1），离线可用、可子目录部署、EE 禁用。
> 关系：**承接 PRD-03**（页面属性数据层已落地，字段与后端不推翻）；**与 PRD-04 标签系统深化协同**（标签作为一等属性，复用 `TagChip` / `space_tags`）。
>
> **一句话价值**：页面属性从「正文顶部平铺 5 个空字段的必填表单」改为「**默认几乎不可见、按需渐进披露、能自动回填就不让用户填**的轻量元数据条」——字段暴露最小化，且在大文档/弱 CPU 的静态阅读态下也可用。

---

## 0. 问题诊断：不是「没做」，是「没接线」

盘查结论：页面属性体系**后端完整、前端组件写好但未接入 UI**，用户看不到入口——这正是「被屏蔽」的真相。

| 层 | 现状 | 结论 |
|----|------|------|
| 后端 | `create-page.dto` 创建期即支持 owner/status/priority/dueAt/tags；更新/批量/过滤/标签聚合齐全；owner 校验 space 成员 | ✅ 完整，本次基本不动 |
| `SearchSpotlightFilters` | `search-spotlight.tsx:151` 在用 | ✅ 活的 |
| `PagePropertiesPanel` | `full-editor.tsx` 渲染树**不引用**它 → 页面上无任何属性入口 | ⛔ 孤儿组件，需重构并挂载 |
| `SpacePageManage` | `App.tsx` **无** `/s/:spaceSlug/manage` 路由 → 无入口 | ⛔ 补路由即可激活 |

原 `PagePropertiesPanel` 的交互缺陷（弃用理由）：把 Owner/Status/Priority/Due/Tags **5 个字段一次性 `Group grow` 平铺**在正文顶部，空字段也占位、全部手填、挤占阅读黄金位——与「字段少 / 自动回填」诉求正相反。

---

## 1. 目标与非目标

### 1.1 目标（均已与需求方确认）

- **字段暴露最小化**：默认页面几乎看不到属性噪音；空属性不占位。
- **自动回填优先**：能由系统推断的默认值不让用户手填。
- **标签一等化**：标签作为常驻可点击属性，打通 PRD-04 治理与直达页。
- **阅读态可用**：大文档 / 国产机的 readMode 静态阅读下，属性条独立于 Yjs 编辑器照常渲染。

### 1.2 非目标

- 不改动 PRD-03 已定的字段集与数据类型（owner/status/priority/dueAt/tags）。
- 不引入新的自定义字段类型（公式/关联/JSON）。
- 不做标签与权限联动（延续 PRD-04：反模式，永久非目标）。
- 不引入任何外网调用；不在 EE 目录新增/恢复功能。

---

## 2. 设计总纲：三个杠杆

属性是「可选的结构化元数据」，不是「每页必填表单」。用三个杠杆同时压住「字段少」与「自动回填」：

| 杠杆 | 作用 | 归属 |
|------|------|------|
| ① 空间级属性开关 | 管理员决定「本空间暴露哪些属性」，关掉的属性在该空间所有页面消失 | 空间设置 |
| ② 页面级渐进披露 | 页面只显示**已填**的属性，空的收进「+ 属性」 | 页面属性条 |
| ③ 自动回填 | Owner 默认创建者 / 父页继承 / 标签智能推荐 | 创建与编辑链路 |

## 3. 交互设计

### 3.1 呈现形态：标题下 inline 属性条（已确认）

位置：`TitleEditor` 与正文之间，一行紧凑 chips。**空属性不占位**。

```
纯文档页（多数页面：几乎无噪音）
  ┌──────────────────────────────────────────┐
  │  # 接口鉴权说明                             │
  │  🏷 api-design   team/backend      + 属性   │  ← 只有标签；owner=创建者弱化显示
  │  ──────────────────────────────────────    │
  │  正文……                                    │

任务型页（按需长出更多属性）
  ┌──────────────────────────────────────────┐
  │  # Q3 迭代计划                              │
  │  👤 张三  ● In Progress  ⚑P1  📅07-30       │
  │  🏷 team/backend  roadmap          + 属性   │
```

- **就地编辑**：点 chip 原位展开对应控件（Owner=成员搜索、Status=空间状态集、Priority=P0–P3、Due=日期时间、Tags=带色联想）。
- **+ 属性**：幽灵按钮，点开 popover 仅列「本空间已启用且当前未填」的属性；选中即插入并聚焦编辑。
- **移除**：编辑态 chip 尾部 `×` 清空该属性（回到未填、收回 popover）。
- **保存时机**：统一「失焦 / 选定即存」，走既有 `useUpdatePageMutation`；去抖避免频繁写。
- **权限**：无编辑权限者，属性条为只读展示（chip 不可点开，标签仍可点击跳转）。

### 3.2 readMode（静态阅读态）兼容

`full-editor.tsx` 现有两分支：`readMode → ReadonlyPageSnapshot`、编辑态 → `TitleEditor + PageEditor`。属性条**两分支都挂**：

- 属性数据来自 `usePageQuery`（REST），**不依赖 Yjs / Hocuspocus / Tiptap 初始化** → 大文档、弱 CPU 下也能秒显、可编辑属性而无需进重编辑器。
- 这条与 `context.md` 的性能线一致：属性是元数据，不该被协同编辑器绑架。

### 3.3 字段收敛：空间开关 +（默认全开）渐进披露（已确认）

- 空间设置新增「页面属性」配置：`[✓] 标签 [✓] 负责人 [ ] 状态 [ ] 优先级 [ ] 截止`。关闭项在该空间任何页面都不出现（属性条与「+ 属性」均不含）。
- **默认全部启用**：日常「字段少」由渐进披露（只显示已填）保证；开关用于管理员**彻底移除**某属性的强控制。存量与新建空间默认全开，兼容不破坏。
- 权限：空间管理员（CASL `Manage / Settings`）。

### 3.4 自动回填（已确认三项，P1 一项）

| 项 | 规则 | 落点 |
|----|------|------|
| **Owner 默认创建者** | 新建页 `ownerId ??= creatorId` | 后端 `page.service.create`（未显式传 owner 时回填） |
| **父页属性继承** | 新建**子页**时，把父页 `propertyTags` + `propertyOwnerId` 作为**预填建议**（灰显，一键采纳/忽略），非强制写入 | 前端创建流程读取父页 → 预填 payload/建议条 |
| **标签智能推荐** | 加标签时联想置顶 = 父页标签 + 本空间高频标签（来自 `space_tags` / `getSpacePropertyTags` 计数）；**只推荐不自动写** | 前端 `TagsInput` 数据源排序 |
| 标题关键词匹配标签（P1） | 依标题/正文关键词匹配已有标签做推荐 | 后置 |

> Owner 默认创建者后，owner chip 会常驻；当 `owner == 创建者且未被手改`时 UI **弱化显示**（浅色头像），避免噪音又保留信息。

### 3.5 与标签管理（PRD-04）打通

- 属性条标签用 PRD-04 的 **`TagChip`**：带颜色、命名空间前缀分段、点击跳 `/s/:space/t/:tag` 直达页。
- 加标签联想带颜色、按高频 + 父页继承置顶。
- 治理（重命名/合并/删除/颜色）归空间设置（PRD-04），属性条只消费 —— **读写解耦**。

## 4. 数据与后端改动（最小）

### 4.1 空间启用属性配置（扩展既有表，非新表）

`space_page_property_configs`（PRD-03 已建，现存 `status_options jsonb`）**新增一列**：

```
alter table space_page_property_configs
  add column enabled_properties jsonb not null
  default '["tags","owner","status","priority","dueAt"]'::jsonb;
```

- 迁移文件：`YYYYMMDDTHHMMSS-space-enabled-properties.ts`（对齐命名规范）。
- `db.d.ts` 由 `migration:codegen` 生成，**禁止手改**。
- 读接口在既有空间属性配置查询上带出 `enabledProperties`；写接口校验值 ∈ 合法属性键集合。

### 4.2 create 回填 owner

`page.service.create`：构造属性时 `ownerId = createPageDto.ownerId ?? actorUserId`。仍复用 `assertValidOwner` 校验（创建者天然是 space 成员，通过）。

### 4.3 父页继承数据来源

前端新建子页时读父页 `propertyTags` / `propertyOwnerId`（`usePageQuery` 已返回），组装预填建议；后端无需改动（create DTO 已支持这些字段）。

### 4.4 不触发的副作用

- 属性变更（尤其 owner 回填、标签）**不触发 AI 重嵌入**（不改正文）。
- 属性写入沿用页面更新链路，遵循既有 CASL 与并发规则。

## 10. 风险与权衡

| 风险 | 对策 |
|------|------|
| owner 默认创建者致 chip 泛滥 | owner==创建者且未手改时弱化显示，信息保留、噪音降低 |
| 就地编辑与只读态逻辑分叉 | 组件内单一 `editable` 开关驱动，readMode 传只读 |
| 父页继承误带无关属性 | 采用「建议式」非强制写入，用户一键忽略 |
| enabled_properties 值非法 | 写接口白名单校验；前端只渲染合法键 |
| 与 PRD-04 未同步落地 | `TagChip`/直达页未就绪时，标签先降级为无色不可跳的纯文本 chip，后续接入 |
