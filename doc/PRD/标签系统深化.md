# PRD-04：标签系统深化（Tags v2）

> 状态：待评审（未开发）
> 版本：v0.1
> 日期：2026-07-25
> 定位：`mydocmost` 内网 / 离线定制 Fork（上游 Docmost v0.24.1），保持离线可用、可子目录部署、EE 禁用。
> 前置依赖：**PRD-03 页面属性体系**（标签已作为 `pages.property_tags text[]` 落地，本 PRD 是其「标签」维度的深化，不重建轮子）。
>
> **一句话价值**：把「散落在页面属性里的扁平标签」升级为「可管理、可点击、可用 URL 直达、可在搜索框用 `tag:` 语法过滤」的轻量标签体系——在**不引入独立标签关系表、不破坏空间权限边界**的前提下。

---

## 0. 为什么写这份 PRD：先纠正认知

社区/竞品路线图里常见的「标签升级建议」大多假设「标签系统很浅、连搜索过滤都没有」。**这个前提在本仓库不成立**。本仓库标签不是独立系统，而是 PRD-03 页面属性体系的一个子字段，且已经具备相当能力。本 PRD 的第一价值就是**盘清「已有」与「真缺口」，避免重复造轮子**。

### 0.1 已实现（勿重复开发）

| 能力 | 现状位置 |
|------|----------|
| 单页打多个标签 + 空间内联想 | 属性面板 `apps/client/.../page-properties-panel.tsx` 的 `TagsInput`；`POST /api/pages/properties/tags`（`getSpacePropertyTags`） |
| **搜索按标签过滤** | 后端 `search.service.ts`：`exists (select 1 from unnest(pages.property_tags) as tag where lower(tag) in (…))`；前端 Spotlight 已有标签过滤控件 `search-spotlight-filters.tsx:389` |
| 页面管理列表按标签过滤 | `POST /api/pages/manage/list`（`PageManageListDto.tags` + `getPageManageList`） |
| 批量改标签（≤500 页） | `POST /api/pages/properties/batch-update`（`PagePropertiesBatchUpdateDto`） |
| 数据层性能与一致性 | `pages.property_tags text[]` + GIN 索引 `pages_property_tags_gin_idx`；`normalizeTags()` 统一 trim + 小写 + 去重 |

> 结论：**「标签无法用于精细化搜索过滤」在本仓库是错误判断**，搜索/列表的结构化标签过滤前后端均已可用。

### 0.2 真正的缺口（本 PRD 要补的）

1. **无集中管理**：不能重命名 / 合并 / 删除标签，看不到使用计数，没有标签云 → 标签越用越乱、同义标签泛滥（`api-design` / `apidesign` / `api设计`）。
2. **无 URL 直达**：没有「某标签下所有页面」的路由页；页面/列表/搜索结果里的标签**不可点击**。
3. **无 `tag:` 搜索语法糖**：现在只能用独立 UI 控件过滤，搜索框里打 `tag:api-design status:draft` 不被解析。
4. **标签扁平**：无层级/分类，多团队共用空间时命名易撞车。

## 1. 目标与非目标

### 1.1 目标

- **可治理**：空间管理员能在一处看到本空间全部标签（含使用计数）、重命名、合并、删除、设置颜色/描述。
- **可导航**：任意标签在页面属性面板、页面管理列表、搜索结果中**可点击**，跳转到「该空间下该标签的所有页面」列表页，且该页有稳定 URL 可分享。
- **可检索**：搜索框支持 `tag:` / `status:` / `priority:` 等前缀语法糖，等价映射到现有结构化过滤字段（后端零改动即可复用）。
- **轻量分层**：用命名空间前缀约定（`team/backend`）+ 展示层前缀聚合，满足「分类」诉求，**不引入树形层级表**。

### 1.2 非目标（明确拒绝，含理由）

- ❌ **标签与权限联动（「某些标签自动归类到特定空间」）**：反模式。标签是「空间内的内容维度」，空间是「权限边界」（CASL）。让标签驱动空间归属会破坏权限模型、制造隐式数据搬运与越权风险。**永久非目标**。
- ❌ **独立 `tags` / `page_tags` 关系表**：本次不做。页面标签的真相来源仍是 `pages.property_tags` 数组（KISS，复用现有索引与全部过滤链路）。见 §4 决策记录。
- ❌ **真正的多级层级树 / 分类字典**：以命名空间前缀约定替代（§3.5）。
- ❌ **跨空间统一标签字典**：延续 PRD-03 的非目标；全局标签聚合仅作为可选只读视图（§3.2，非 MVP）。
- ❌ 标签级权限、标签订阅/关注、标签自动打标（AI 推荐标签）——均非本期范围。
- ❌ 任何外网调用（遥测/CDN/外链）——延续仓库硬约束。

## 2. 术语

| 术语 | 说明 |
|------|------|
| 标签（Tag） | 归一化后的字符串（小写、trim、去重），存于 `pages.property_tags` 数组元素，**空间范围**语义。 |
| 元数据侧车（`space_tags`） | 可选的标签元数据表（颜色/描述等），**不是标签真相来源**，惰性登记，缺失不影响标签可用。 |
| 命名空间前缀 | 标签中 `/` 之前的部分（`team/backend` 的 `team`），仅约定 + 展示层聚合，无独立存储。 |
| 标签直达页 | `/s/:spaceSlug/t/:tag`，展示某空间下某标签的全部页面。 |
| 语法糖（mini-query） | 搜索框里 `tag:x status:y` 形式的过滤前缀，前端解析后映射到既有 `SearchDTO` 字段。 |

## 3. 功能范围（MVP）

### 3.1 标签管理面板（空间设置内）

入口：空间设置区新增「标签」页（毗邻现有 `space-page-property-settings.tsx` 的属性/状态配置）。权限：空间管理员（CASL `Manage / Settings`）。

- **标签云 / 列表**：列出本空间全部标签，每项含「名称、使用计数、颜色点、命名空间前缀分组」。计数支持排序（高→低）。计数**实时聚合**得出（§4.3），不落缓存列。
- **重命名**：`a` → `b`。级联更新所有 `property_tags` 含 `a` 的页面（§5.2），并处理与已存在 `b` 的合并去重。
- **合并**：多个源标签 → 一个目标标签（重命名的多源版本）。
- **删除**：从所有页面数组移除该标签（`array_remove`），并删除其 `space_tags` 元数据行。
- **设置元数据**：颜色（预设色板中选一）、可选描述。首次设置时**惰性创建** `space_tags` 行。
- 所有写操作要求二次确认（影响页面数会在确认框中显示）。

### 3.2 标签直达页（URL 可分享）

- 路由：`/s/:spaceSlug/t/:tag`（**空间内为主**，贴合 per-space 语义；`:tag` 需 URL encode 以容纳 `/`、中文等）。必须兼容 `BASE_PATH`（走 react-router `basename`，与现有路由一致）。
- 内容：标签元数据头（名称/颜色/描述/计数）+ 该标签下页面列表（**直接复用 `POST /api/pages/manage/list`**，已支持 `tags` 过滤、分页、排序）+ 「相关标签」（与本标签共现的 Top N 标签，P1）。
- 鉴权：按用户对该 space 的可读权限（manage/list 已内建鉴权）。无权/空结果给出友好空态。
- （可选，非 MVP）全局只读聚合视图 `/tags/:tag`：跨「用户可读空间」聚合，需显式按 `allowedSpaceIds` 过滤；同名标签跨空间语义可能不一致，仅作发现用途。

### 3.3 可点击标签

将以下位置的标签 chip 变为指向标签直达页的链接（同时保留在管理列表中「点击=加入过滤」的既有交互，二者通过点击区/修饰键区分）：

- 页面属性面板 `page-properties-panel.tsx` 的标签展示态；
- 页面管理列表 `space-page-manage.tsx` 的标签列；
- 搜索结果项 `search-result-item.tsx`。

### 3.4 搜索框 `tag:` 语法糖（纯前端解析，后端零改动）

在 Spotlight 搜索输入上加一层 **mini-query 解析器**，把前缀 token 抽出、其余作为全文 `query`，映射到既有 `SearchDTO` 字段：

| 语法 | 映射字段 | 说明 |
|------|----------|------|
| `tag:api-design` | `tags: ['api-design']` | 可重复：`tag:a tag:b` → `['a','b']` |
| `tag:"api design"` | `tags: ['api design']` | 引号包裹含空格/特殊字符 |
| `status:draft` | `status: ['draft']` | |
| `priority:P1` | `priority: ['P1']` | 校验属于 `PAGE_PRIORITY_OPTIONS` |
| `owner:<id>` | `ownerIds: ['<id>']` | 值为用户 id（P1 支持 `@name` 联想解析） |
| 其余文本 | `query` | 全文关键词 |

- 解析结果与现有过滤控件**双向同步**（在框里打 `tag:x` 会点亮标签过滤控件，反之亦然）。
- 未识别前缀（如 `foo:bar`）按普通文本处理，不报错。
- 前缀通配 `tag:team/*` 归入 §3.5（P1）。

### 3.5 命名空间前缀约定（层级的轻量替代）

- 约定：以 `/` 分隔命名空间，如 `team/backend`、`type/rfc`。**不新增任何存储**，`property_tags` 仍存完整字符串。
- 展示层：管理面板与直达页按第一段前缀**分组/着色**；标签联想按前缀排序。
- （P1）搜索前缀通配：`tag:team/*` → 后端加一条 `exists(... where tag like 'team/%')` 分支（届时再评估后端小改）。MVP 只做精确匹配 + 前端分组。

## 4. 数据模型与关键决策

### 4.1 决策：沿用内嵌数组 + 轻量元数据侧车（已确认）

页面标签的**真相来源仍是 `pages.property_tags text[]`**（复用 GIN 索引与全部现有过滤）。新增一张**可选**元数据表 `space_tags`，只承载「标签的附加属性」（颜色/描述），**不承载「哪些页面有此标签」**。

设计要点：`space_tags` 是**惰性登记的侧车，不是真相来源**——

- 用户在页面直接新建的标签**无需**先在 `space_tags` 登记即可使用（与现状一致，零摩擦）。
- 管理面板展示时：以「`property_tags` 聚合出的真实标签集」为准，`LEFT JOIN space_tags` 补充元数据。侧车里有、但已无任何页面引用的标签，视为「孤立元数据」，可在删除标签时一并清理。

### 4.2 `space_tags` 表（新增迁移）

迁移文件：`apps/server/src/database/migrations/YYYYMMDDTHHMMSS-space-tags.ts`（时间戳按创建时刻）。对齐 PRD-03 的 `space_page_property_configs` 风格（同带 `space_id + workspace_id`，级联删除）。

```
space_tags (
  id            uuid  pk default gen_random_uuid(),
  space_id      uuid  not null references spaces.id     on delete cascade,
  workspace_id  uuid  not null references workspaces.id on delete cascade,
  name          varchar not null,   -- 归一化(小写/trim)后的标签名，空间内唯一键
  color         varchar,            -- 可选，取自前端预设色板
  description   varchar,            -- 可选
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now(),
  unique (space_id, name)
)
```

- `db.d.ts` 由 `migration:codegen` 生成，**禁止手改**。
- MVP 字段仅 `color`/`description`；`display_name`（保留展示大小写）列为 P1。
- **不设 `usage_count` 缓存列**：计数实时聚合（§4.3），避免缓存一致性维护成本。

### 4.3 使用计数：实时聚合，不落库

管理面板 / 标签云所需计数由单条聚合得出（低频操作，可接受）：

```
select tag, count(*) as cnt
from pages, unnest(pages.property_tags) as tag
where pages.space_id = :spaceId and pages.deleted_at is null
group by tag
order by cnt desc;
```

与 `space_tags` 元数据 `LEFT JOIN` 合并为管理面板数据源。

## 5. 后端设计

### 5.1 新增 / 复用接口

| 端点 | 用途 | 备注 |
|------|------|------|
| 复用 `POST /api/pages/manage/list` | 标签直达页取页面列表 | 已支持 `tags`/分页/排序，**无需新增** |
| `POST /api/spaces/tags/list` | 管理面板数据源：聚合计数 + 元数据 join | 新增，鉴权 `Manage/Settings` 读；返回 `[{ name, count, color?, description?, namespace? }]` |
| `POST /api/spaces/tags/rename` | 重命名/合并（源可为多个） | 新增，`Manage/Settings`；body `{ spaceId, from: string[], to: string }` |
| `POST /api/spaces/tags/delete` | 删除标签 | 新增，`Manage/Settings`；body `{ spaceId, names: string[] }` |
| `POST /api/spaces/tags/metadata` | 设置颜色/描述（惰性 upsert `space_tags`） | 新增，`Manage/Settings` |

> 端点归属：标签是空间级治理，放入 space 域（`core/space` 下新增 `space-tags.controller/service` 或并入现有 space 控制器），与 PRD-03 的空间属性配置同级。

### 5.2 重命名 / 合并 / 删除的 SQL 语义（原子、单语句、去重、不动 updated_at）

- **重命名/合并** `from[] → to`（`to`、`from` 均先 `normalizeTags`）：对每个 `f ∈ from`，将含 `f` 的页面数组中的 `f` 替换为 `to` 并整体去重。实现用一条基于 `array` 重写的 UPDATE（`array_replace` + 去重，或 `array(select distinct …)` 重建），`where space_id = :spaceId and property_tags && :from`。
- **删除** `names[]`：`update pages set property_tags = (select array(select distinct e from unnest(property_tags) e where e <> all(:names))) where space_id=:spaceId and property_tags && :names`。
- **关键规则：不刷新 `updated_at`**。标签治理是元信息变更，不应把大量页面顶到「最近更新」。UPDATE 需显式保持 `updated_at` 不变（绕过/不触发更新时间戳逻辑）。
- 同步维护 `space_tags`：重命名时迁移/合并元数据行；删除时移除对应行。
- 事务包裹页面 UPDATE 与 `space_tags` 变更，保证一致性。
- **AI 索引**：标签变更不改正文，**不触发**页面重嵌入（避免无谓的 `AI_QUEUE` 负载）；仅需前端 query 失效。

### 5.3 鉴权与规则

- 给单页打/改标签：沿用现状——页面编辑权限。
- 标签治理（rename/merge/delete/metadata）：空间管理员 `Manage / Settings`。
- 标签直达页数据：按用户对 space 的可读权限（manage/list 已鉴权）。
- 归一化统一走既有 `normalizeTags()`（trim + 小写 + 去重），前后端一致。

## 6. 前端设计

- **标签管理页**：空间设置内新增 tab（`features/space/components/space-tags-settings.tsx`）。标签云（按计数权重/字号）、行内重命名、多选合并、删除确认（显示受影响页面数）、颜色选择器、描述编辑。TanStack Query 管理数据与失效。
- **标签直达页**：新增路由页（`pages/space/space-tag-pages.tsx`），复用 manage/list 查询与页面列表组件；顶部标签元数据头；空态/无权限态。
- **可点击标签组件**：抽一个 `TagChip`（`features/page/components/tag-chip.tsx`），统一渲染颜色 + 命名空间前缀 + `Link` 到直达页；在属性面板、管理列表、搜索结果三处复用。
- **搜索语法解析器**：`features/search/utils/parse-search-query.ts`，纯函数，输出 `{ query, tags, status, priority, ownerIds }`；接入 Spotlight，与过滤控件双向同步。
- **配置**：如需新暴露开关（如全局聚合视图门控），遵循「`window.CONFIG` 注入 + `lib/config.ts` 两端读取」约定；MVP 预计无需新增运行时配置。

## 9. 指标与验收

**指标**

- 标签治理动作（重命名/合并/删除）月活空间数 ≥ 目标值（衡量「可治理」被使用）。
- 经由标签直达页 / `tag:` 语法进入的页面浏览占比 ≥ 15%（衡量「可导航/可检索」）。
- 同义标签数量随时间下降（合并生效）。

**验收清单**

- [ ] 空间设置「标签」页可见全部标签 + 实时计数，可按计数排序。
- [ ] 重命名/合并/删除生效，级联更新页面数组并去重，**不改动页面 `updated_at`**，不触发 AI 重索引。
- [ ] `space_tags` 惰性登记：直接在页面新建的标签无需预登记即可使用；设颜色/描述后正确 upsert。
- [ ] `/s/:spaceSlug/t/:tag` 在带 `BASE_PATH` 部署下可访问、可分享，列表复用 manage/list、含分页排序。
- [ ] 属性面板/管理列表/搜索结果中的标签可点击跳转直达页。
- [ ] 搜索框 `tag:x status:y priority:P1` 正确解析并与过滤控件双向同步；未识别前缀不报错。
- [ ] 管理面板按命名空间前缀分组展示。
- [ ] 权限：非空间管理员无法治理标签；无 space 读权限者访问直达页得空态。
- [ ] `pnpm server:build`、`pnpm client:build`（Node22）通过；改动文件 ESLint/Prettier 通过。

## 11. 风险与权衡

| 风险 | 说明 | 对策 |
|------|------|------|
| 大空间计数聚合慢 | `unnest + group by` 在超大空间偏慢 | 低频管理操作可接受；必要时加物化/缓存（延后，勿过早优化） |
| 重命名误操作影响面大 | 一次改名波及很多页面 | 确认框显示受影响页面数；操作在事务内；保留操作日志（P1） |

| 语法糖与自由文本歧义 | 用户正文里真的想搜 `tag:` 字面量 | 仅识别已知前缀白名单；未知前缀按文本；支持引号转义 |
